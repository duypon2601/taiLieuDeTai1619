## 6. Luồng end-to-end đã chốt (để trình bày)

Nguồn: spec `docs/spec/DATA-16_MASTER_SPEC_v2.md` §3 (kiến trúc), §5.1 (graph), §8 (insight); ADR-006 (yêu cầu sửa); đối chiếu với code `src/agent/graph.py` và `src/agent/routing.py`.

**A. Đăng nhập.** Người dùng đăng nhập, backend cấp JWT chứa role (Admin/Builder/Viewer), region và allowed_projects. Chỉ Builder và Admin được chat; Viewer chỉ xem thư viện. [Thật]

**B. Một lượt chat.** Builder gõ câu hỏi → `POST /chat/stream` (SSE) → ghi audit PROMPT_INPUT → chạy graph LangGraph (thread = conversation_id, checkpoint Postgres). Frontend nhận từng event `step` để hiển thị stepper.

1. `guard_input`: regex chặn prompt injection và câu quá dài → `blocked`. [Thật]
2. `route_intent` (LLM): phân loại thành new_dashboard / refine / clarify / out_of_scope. [Mock]
   - clarify → `ask_clarification` trả các lựa chọn chỉ số. [Thật]
   - out_of_scope → câu từ chối cố định. [Thật]
3. `extract_entities` (LLM): lấy ra dự án, metric, chiều phân tích, thời gian. [Mock]
4. `check_access`: dự án ngoài vùng hoặc ngoài whitelist → `deny_access`. [Thật]
5. `build_cube_queries` (LLM): sinh Cube query dựa trên danh sách member hợp lệ. [Mock]
6. `validate_queries`: dry-run trên Cube. Nếu lỗi, quay lại bước 5 (tối đa 3 lần); hết lượt thì báo lỗi TIME_RANGE_REQUIRED hoặc CUBE_QUERY_FAILED. [Thật, chạy trên MockCube]
7. `load_data`: `/load` từ Cube; `queryRewrite` tự thêm RLS theo vùng và bắt buộc dateRange. [Logic thật, dữ liệu mock]
8. `advise_charts`: chọn loại biểu đồ theo luật R1–R10 và dựng layout lưới 12 cột, không dùng LLM. [Thật]
9. `compute_facts`: code tính các con số (tổng, max/min, tỷ trọng, % thay đổi). [Stub]
10. `write_insights` (LLM): viết 2–3 câu, mọi con số dùng placeholder `{{fact_id}}`. [Mock]
11. `verify_insights`: thay placeholder bằng số thật, rồi lắp DashboardSpec (pending_review). Fail thì viết lại 1 lần. [Thật một phần: chưa bắt chữ số bịa và từ nhân quả]
12. `hitl_review`: `interrupt()`, graph dừng. Backend lưu bản nháp vào Postgres và ghi audit DRAFT_GENERATED; SSE gửi `draft_ready`, UI hiển thị dashboard nháp. [Thật]

**C. Duyệt (HITL).** Builder bấm Duyệt hoặc Từ chối → `POST /dashboards/{id}/review` (có kiểm tra version) → `Command(resume=...)`.
- Duyệt → `publish` → status published, ghi audit HITL_APPROVED và DASHBOARD_PUBLISHED. [Thật]
- Từ chối → rejected. [Thật]
- Yêu cầu sửa: không đi qua endpoint review mà gửi lượt chat mới cùng conversation_id (ADR-006), để câu sửa vẫn phải qua guardrail. `route_intent` nhận ra đã có bản nháp nên trả `refine` → `plan_refinement` (LLM, [Mock]):
  - Chỉ đổi cách trình bày → nhảy thẳng tới `advise_charts`, dùng lại dữ liệu cũ.
  - Đổi dữ liệu → quay lại `check_access` và dựng lại query.
  - Bản nháp cũ chuyển superseded, bản mới có version + 1.

**D. Xem dashboard.** Thư viện `GET /dashboards` lọc theo vùng và role. Mỗi widget gọi `POST /widgets/{id}/data`: server lấy query đã duyệt từ DB (client không gửi query tự do), chỉ cho phép filter trong whitelist, gọi Cube theo quyền user và ghi audit. [Thật, dữ liệu mock]
